## Phase 1: indicator computations

- Status: DONE
- Commit: `2ad7773` fix: [behavior-change] repair 17 broken indicator computations
- Errors addressed: 11 `Unexpected error with indicator`, 30 `Could not calculate
  indicator` DEBUG lines per cycle.

17 of 98 registered indicators could never return a value. Four distinct
causes, all reproduced with a synthetic 300-candle OHLCV frame before the fix:

- `adi`, `atr_bands`, `hma`, `zlema`, `ma_ribbon` passed a pandas Series to
  talib/pandas_ta, which preserves the DatetimeIndex, and then indexed the
  result with `[-1]`. That is a label lookup, so it raised `KeyError: -1`.
- `eom`, `rvi` treated a single-output pandas_ta Series as a DataFrame, so
  `.iloc[-1].isna()` ran against a numpy scalar.
- `qqe`, `gann_hilo`, `supertrend`, `psar`, `ichimoku`, `pvi` checked
  `iloc[-1].isna().any()` on a multi-column frame whose long/short columns are
  mutually exclusive, so one column is always NaN and the guard always fired.
- `dpo` is forward-shifted; its last row is NaN by construction.

`rmi`, `tii` and `vw_rsi` called functions that pandas_ta 0.4.71b0 does not
expose (`AttributeError: module 'pandas_ta' has no attribute ...`). They are now
computed from their published definitions: RMI is RSI over momentum, TII is the
rolling ratio of positive to total deviation from the SMA, VW-RSI is Wilder's
RSI with volume-weighted gains and losses.

`features/indicators/base.py` gained `last_finite_value` and `finite_column`,
which reduce Series, DataFrame, ndarray and scalar results to the last finite
value, so a shape mismatch can no longer be reported as "NaN".

Behaviour change: `supertrend`, `psar` and `ichimoku` carry weights 15/10/18 in
`indicator_weights.json` and `AnalysisScorer.score_technical_results` normalises
by the weight of the indicators that are present. Restoring them therefore
changes the technical score and the emitted signals. The golden baselines were
not re-recorded here, per `docs/open_issues.md`.

## Phase 2: upstream outages reported once

- Status: DONE
- Commit: `c8186f7` fix: report upstream outages once instead of once per symbol
- Errors addressed: 49 `Error in _fetch ... Circuit breaker is OPEN` tracebacks,
  2 duplicate Redis connection warnings.

`CircuitBreakerError` now derives from `UpstreamUnavailableError`, so an open
breaker reaches callers through the existing "source is down" contract instead
of the generic handler in `BinanceFetcher._fetch`, which logged a traceback per
rejected call. The breaker itself announces the CLOSED->OPEN transition once at
WARNING and the recovery once at INFO.

`ResourceManager` reset its client to `None` on a failed connect, so every later
call repeated a 10 s DNS attempt and re-logged the same warning.

## Phase 3: rate limiter lock

- Status: DONE
- Commit: `354b8a0` fix: stop the rate limiter from stalling every endpoint while it waits
- Errors addressed: 7 `Rate limit hit for cpi. Sleeping for 36.76s` events, each
  freezing every other AlphaVantage endpoint for the whole window.

`RateLimiter.wait_if_needed` awaited `asyncio.sleep` while holding its own
`asyncio.Lock`. The wait is now computed under the lock and slept outside it,
then the window is re-checked in a loop; the per-endpoint cap is unchanged.

## Phase 4: enrichment outages reported once

- Status: DONE
- Commit: `ada137d` fix: log enrichment outages once instead of once per symbol
- Errors addressed: 8 per-symbol Binance `get_*` errors, 7 `Error fetching
  trending data` / `get_fundamental_data`, 10 `News fetch failed` warnings.

All nine enrichment handlers in `data/data_provider.py` logged ERROR although
they return `None` by contract and the caller degrades. They and
`data/sources/news_fetcher.py` now route through a helper that keeps the
original level for unexpected failures and drops `UpstreamUnavailableError` to
DEBUG, because the source's breaker already announced the outage once.

## Not fixed here

- Golden baselines: must be re-recorded in the Linux CI image, not on this
  workstation. See `docs/open_issues.md`.
- `fapi.binance.com` and `api.coingecko.com` do not resolve on this network
  (U3). Code cannot fix reachability.
- `get_macro_economic_data` is reached from both the `macro` and
  `market_indices` memo scopes, so one cycle issues two sets of five
  AlphaVantage requests against a 5/minute budget. Collapsing them changes fetch
  timing and needs a proposal.
- `logs/app.log` is gitignored and appended to by every test run; the analysis
  above uses the first 18,628 lines, which end with the 2026-10-24 shutdown.
