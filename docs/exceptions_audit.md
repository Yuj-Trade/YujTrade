# Exceptions Audit (v4.0 Phase 6)

Every `except Exception` in non-test production code. No bare `except:` and
no `except BaseException` exist. Every handler logs (with
`logger.opt(exception=...)` where a traceback adds signal) or re-raises; none
swallows silently. loguru ignores the stdlib `exc_info` keyword, so handlers use
`logger.opt(exception=True)` (current exception) or `logger.opt(exception=err)`
(a captured exception). The file sink format includes `{exception}` so these
tracebacks reach `logs/app.log`.

Path classes: `analysis-failure` (a scoring/indicator step degrades but the
analysis continues with a log), `best-effort-IO` (fetch/cache/UI degrades to
None/empty with a log and the caller handles absence), `shutdown` (cleanup
that must not raise, logged).
